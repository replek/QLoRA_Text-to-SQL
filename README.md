# QLoRA Instruction Fine-Tuning for Text-to-SQL

Проект посвящён инструктивному дообучению языковых моделей для задачи Text-to-SQL: генерации SQL-запросов по естественно-языковым вопросам и схемам баз данных.

## Цель проекта

Основная цель - исследовать, насколько эффективно можно адаптировать относительно небольшую языковую модель под Text-to-SQL при ограниченных вычислительных ресурсах.

Вместо полного fine-tuning используется QLoRA: базовая модель загружается в 4-битном виде и остаётся замороженной, а в процессе обучения обновляются только компактные LoRA-адаптеры.

## Задача

Модель получает:

text instruction + database schema + natural-language question 

и должна сгенерировать один корректный SQLite-запрос:

sql SELECT ... 

В проекте рассматриваются типичные проблемы Text-to-SQL:

- выбор правильных таблиц
- выбор существующих колонок
- построение корректных JOIN
- использование агрегатных функций
- фильтрация, сортировка и группировка
- обработка вложенных запросов
- генерация UNION, INTERSECT и EXCEPT
- снижение числа галлюцинаций

## Используемый benchmark

Для обучения и оценки используется [Spider 1.0](https://yale-lily.github.io/spider) - cross-domain benchmark для сложного Text-to-SQL.

[Официальный репозиторий Spider](https://github.com/taoyds/spider)

## Оценка качества

Для оценки используются официальные метрики Spider:

- execution accuracy
- exact match
- partial matching
- accuracy по уровням сложности:
  - easy
  - medium
  - hard
  - extra

Дополнительно используется метрика [Test Suite Accuracy](https://github.com/taoyds/test-suite-sql-eval), которая сейчас используется в официальных соревнованиях по данному датасету.

## Основные идеи проекта

Сначала мы дообучаем модель Qwen2.5-Coder-1.5B-Instruct с помощью QLoRA с разными рангами матрицы. Затем проверяем, как на качество влияют улучшенный промт, веса для более сложных примеров и аугментация данных. После этого отдельно тестируем улучшенный inference-пайплайн с дополнительной проверкой сгенерированных SQL-запросов через SchemaGuard. На следующем этапе повторяем эксперимент с более крупной моделью Qwen2.5-Coder-7B-Instruct и сравниваем, насколько увеличение размера модели влияет на итоговое качество.

## SchemaGuard

В проекте реализован модуль SchemaGuard, который анализирует сгенерированные запросы и выявляет:

- несуществующие таблицы
- несуществующие колонки
- ошибки alias
- неоднозначные ссылки на колонки
- подозрительные JOIN
- синтаксически или семантически неисполняемые SQLite-запросы

SchemaGuard используется как диагностический инструмент и как основа для экспериментов с автоматическим исправлением SQL
